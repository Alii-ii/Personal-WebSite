# 核心文档格式规范

本文件定义四份核心文档（requirements.md / design.md / tasks.md / qa.md）的格式规范和增量更新规则。

---

## requirements.md — 需求规范

### 格式：EARS（Easy Approach to Requirements Syntax）

```markdown
# 需求文档 - [功能名称]

## 初始需求 - [YYYY-MM-DD]

### Requirement: [需求名称]
WHEN [condition], THE SYSTEM SHALL [behavior]

#### Scenario: [场景描述]
- GIVEN [initial state]
- WHEN [trigger]
- THEN [expected outcome]
- AND [additional outcomes]

### Requirement: [需求名称 2]
...

### 约束与边界
- [约束条件]

### 置信度评估
| 需求 | 置信度 | 说明 |
|------|--------|------|
| [需求1] | 95% | [说明] |
```

### 增量更新（UPDATE 模式）

在文档末尾追加，不修改已有内容：

```markdown
---

## 迭代 2 - [YYYY-MM-DD]

### 新增需求
[新增的需求，同样使用 EARS 格式]

### 修改的需求
[修改的需求，保留原文并标注变更]
**← 变更说明**：[说明变更内容和原因]

### 删除的需求
**状态**：❌ 已删除
**原因**：[删除原因]
**迁移方案**：[替代方案]
```

## tasks.md — 任务清单

### 格式

任务拆分策略遵循项目 rules 中的约定。以下是通用结构：

```markdown
# 任务清单 - [功能名称]

## 初始任务 - [YYYY-MM-DD]

### [分类 1] Tasks

- [ ]   1. [大任务名称]
    - [ ] 1.1 [子任务]
        - [ ] 1.1.1 [具体任务]
        - [ ] 1.1.2 [具体任务]
    - [ ] 1.2 [子任务]

### [分类 2] Tasks

- [ ]   2. [大任务名称]
    - [ ] 2.1 [子任务]
        - [ ] 2.1.1 [具体任务]
```

### 进度更新

实现过程中实时更新：

```markdown
- [x] 1.1.1 Create users table ✅ 2025-12-18
- [x] 1.1.2 Create sessions table ✅ 2025-12-18
- [ ] 1.1.3 Add indexes (in progress)
```

### 增量更新

```markdown
---

## 迭代 2 任务 - [YYYY-MM-DD]

### [分类] Tasks (New)

- [ ]   3. [新任务名称]
    - [ ] 3.1 [子任务]
```

## qa.md — 验收项清单

### 验收类型

| 类型 | 说明 | 验证方式 |
|------|------|---------|
| `自动化` | 可通过脚本验证 | lint / build / 单测 / E2E |
| `人工-交互` | 交互流程、操作反馈、边界状态 | 人工操作确认 |
| `人工-视觉` | 视觉还原、间距、颜色、响应式 | 人工目视确认（有设计稿时适用） |
| `人工-逻辑` | 业务规则、数据边界、异常路径 | 人工逻辑验证 |

### 阻塞级别

| 级别 | 说明 |
|------|------|
| `P0` | 必须通过才能交付 |
| `P1` | 应该通过，可带问题上线但需记录 |
| `P2` | 建议修复，不阻塞 |

### 格式

```markdown
# 验收项清单 - [功能名称]

## 初始验收项 - [YYYY-MM-DD]

| 验收项 | 验收类型 | 阻塞级别 | 验收结果 |
|--------|---------|---------|---------|
| 登录成功后跳转首页 | 人工-交互 | P0 | - |
| 表单校验错误提示正确展示 | 人工-交互 | P0 | - |
| 登录接口 401 时展示错误信息 | 人工-逻辑 | P0 | - |
| 页面在 375px 宽度下不溢出 | 人工-视觉 | P1 | - |
| lint 通过 | 自动化 | P0 | - |
| build 通过 | 自动化 | P0 | - |
```

### 结果更新

- 自动化项：Phase 5 中由 agent 运行验证后更新为 `✅ pass` 或 `❌ fail [原因]`
- 人工项：Phase 5 中提醒用户，由用户手动填写结果

### 增量更新

```markdown
---

## 迭代 2 验收项 - [YYYY-MM-DD]

| 验收项 | 验收类型 | 阻塞级别 | 验收结果 |
|--------|---------|---------|---------|
| [新增验收项] | [类型] | [级别] | - |
```

## 通用增量更新原则

**核心**：保留历史，追加新内容，不覆盖旧内容。

- 每次迭代用 `---` 分隔符和日期标题追加
- 修改已有内容时保留原文并标注变更说明
- 删除的内容标记状态和原因，不物理删除
